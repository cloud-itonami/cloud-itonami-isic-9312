Rollout-gate holds — 1 (NOT governor refusals)

This is the look-alike the classifier has to keep apart. sportsclub.phase/gate holds an op that the current rollout phase has not enabled yet, and the :decide node writes that hold through governor/hold-fact — so the fact type is :governor-hold here too. What separates them is :phase-reason (only the phase gate sets one) and the empty :violations: the governor was clean, the calendar was not. Counting these as refusals would overstate what the governor actually caught.

Approver rejections — 1 (also NOT governor refusals)

The second look-alike, and the sharper one. When a human rejects, operation/build's :request-approval node synthesises a violation — {:rule :approver-rejected} — and merges it over governor/hold-fact. So this rejection fact carries a violation while the governor raised none. Any classifier keyed on :violations being non-empty would count this as a governor refusal. This one keys on :t first, which is :approval-rejected here.

What that scan found in this build

Of 5 human-approved commits, 3 kept the approver (verifications, conduct-screens) and 2 lost it (members, actions). Attribution here is therefore per-effect and lossy — a real, disclosed gap, not something this rendering task quietly patched inside the store.

The audit ledger separately holds 6 committed facts whose actor values are op-1. Approver-shaped keys anywhere in the ledger: none. Does the ledger mention officer-hanako anywhere? no. So the append-only audit trail records which actor ran the operation but not which human authorised it — and the two are not the same person even in this demo.

Where it survives it survives because store/commit-record! persists the record's payload for those effects, and operation/build's :request-approval node only adds approved-by to payload — never to value. Effects whose store branch reads value, or which recompute the record from the member entirely, cannot see it. This paragraph describes the mechanism; the table above is the evidence, and it is re-measured on every build.
